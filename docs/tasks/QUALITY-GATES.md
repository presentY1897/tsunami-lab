# 프로토타입 2 품질 게이트

이 문서의 성능 목표와 시나리오 기준은 `src/` 프로토타입 2의 기록이다. 프로토타입의 코드는 2026-10-01에 저장소에서 지웠다(D-047). git 태그 `prototype-v2`에 마지막 상태가 있다. 아래에 나오는 `src/` 경로, `gpu-solver.spec.ts`, `dev/shoot.mjs`는 그 태그에서만 볼 수 있다. 현재 `app/`의 범위와 남은 검증은 [계획](../PLAN.md), 실행·검사 명령은 [README](../../README.md)를 본다. `npm run check`는 현재 앱을 빌드한다.

변경을 합치기 전에 통과해야 하는 기준이다. 기준을 바꿀 때는 이유를 [결정 이력](../decisions/DECISIONS.md)에 남긴다.

## 1. 자동 검사

```bash
npm run check      # 타입 검사 + 단위 테스트 + 빌드
npm run test:e2e   # 헤드리스 브라우저: GPU 솔버 검증, 앱 구동
```

둘 다 실패 없이 끝나야 한다. e2e는 GPU가 없어도 SwiftShader로 돈다.

## 3. 시나리오 점검 (수동, 물리나 지형 처리를 바꿨을 때)

`node dev/shoot.mjs <프리셋> tiny <분,분,...>`로 돌리고 `dev/shots/`를 본다.

| 시나리오 | 확인할 것 | 기준값 (tiny 해상도에서 얻은 값) |
|---|---|---|
| 2011 도호쿠 → 센다이 평야 | 육지 첫 침수 시각, 내륙 침투 | 64.5분, 80분 시점 4.1 km. 실제는 약 65~70분, 약 5 km |
| 동해 소행성 500 m → 강릉 | 중간, 세밀 격자가 차례로 깨어나는지 | 세밀 격자 약 53분에 활성, 첫 침수 60분 |
| 아무 시나리오의 0초 | 시작 직후 침수 면적이 0인지 | 0 km². 0이 아니면 DEM 합성에 구멍이 생긴 것이다 (D-005) |

## 4. 화면 점검 (수동, 렌더링을 바꿨을 때)

- 해안 시점에서 물이 지형과 만나는 선이 계단지거나 물이 비탈을 타고 올라가 보이지 않는다.
- 바다 전체 시점에서 파면이 색과 기복으로 읽힌다. 지진과 소행성 둘 다.
- 단계 경계에서 지형 음영의 세기가 달라 보이지 않는다.
- 표시 모드(최대 침수심, 도달 시간, 최대 유속)에서 육지 위 물이 색을 가리지 않는다.

## 5. 성능 목표 (T-101에서 실측 예정)

- 보통 해상도, 중급 외장 GPU에서 계산 중 30 fps 이상.
- 세밀 격자가 깨어 있을 때 60배속을 유지.
- 준비 단계(타일 수신과 격자 생성) 20초 이내.

현재 상태: 미측정. 프레임 시간에 따라 계산량을 줄이는 적응 예산은 구현되어 있다.
