# 계획

현재 개발 대상은 `app/`이다. 이 문서는 2026-09-23 기준 구현 상태와 남은 작업을 정리한다. 사용 방법은 [README](../README.md), 설계 변경의 이유와 당시 검증값은 [결정 이력](decisions/DECISIONS.md)에 있다.

[프로토타입 2 정리](PROTOTYPE-V2.md)의 세 지침인 모바일 사용, 면으로 표현한 지형, 정적 호스팅과 작은 다운로드를 따른다. 전송량 상한은 [다운로드 예산](DATA-BUDGET.md)에 있다. 각 단계가 끝나면 보여 주고 확인받은 뒤 다음으로 간다.

## 현재 구조

**기본 모드 — 구현됨.** 삼각형 면으로 된 3D 지구에서 지진이나 소행성 발생원을 놓는다. 전 지구 약 39 km 격자와 발생원 주변 약 8 km 격자에서 파도를 계산한다. 해안을 선택하면 중간 격자와 약 480 m 해안 격자를 추가해 침수를 직접 계산한다. 나머지 해안은 앞바다 파고에서 경험식으로 영향을 추정한다. 두 방식 모두 침수 표현에 사용하며, 선택한 해안에는 침수 면적 등의 통계를 표시한다(D-024~D-026, D-031~D-039).

받는 지형 자료는 약 10 km까지다. 더 세밀한 지형은 보간과 생성한 세부로 채운다(D-018). 기본 모드의 침수는 이 지형 위의 양식화된 표현이며 실제 세밀 지형에 따른 침수 예측과 구분한다. 약 480 m는 위도 38도 부근의 계산 간격이다.

**상세 모드 — 보류.** 사용자가 요청한 해안의 실제 세밀 지형을 받아 240~480 m 격자로 계산하는 별도 흐름이다. 구현할 때는 자료 출처·한계, 예상 다운로드와 준비 시간을 먼저 안내하고 동의를 받는다. 현재 기본 모드의 해안 선택 기능과는 별개다. D-027에서 상세 모드의 우선순위를 뒤로 미뤘다.

## 구현된 범위

| 범위 | 현재 상태 | 결정 이력 |
|---|---|---|
| 자료 | 전 지구 자료, 10 km 조각 생성·디코딩·필요 시 로드·캐시 | D-013~D-018 |
| 지구와 지형 | 지형·물 층 분리, 화면에 따른 메시 세분화, 회전·확대·기울기·방향 조절 | D-019, D-028 |
| 발생원과 계산 | 지진·소행성, 전 지구·발생원·해안 중첩 격자, 침수 통계 | D-020~D-026 |
| 지도 정보 | 실제 해안선·국경, 주요 도시 점·이름, 최대 침수 범위 색칠 | D-027, D-029~D-030 |
| 해안 영향 | 경험식 처오름과 도시 목록, 시간에 따른 침수 표현, 현재 수위 연동, 연결 검사와 주기 기반 거리 제한 | D-031, D-034~D-039 |
| 조작 | 패널 접기·이동, 파도 높이 표현 세 방식, 발생원 미리보기·시작 효과 | D-032~D-033, D-042 |
| 재생과 공유 | 시각 0에서 대기, 배속·시간 슬라이더, 발생원 수정·재실행, 시나리오 링크 | D-043 |
| 종료와 검증 환경 | 자동 정지와 72시간 상한, WSLg 실제 GPU 검증 경로 | D-040~D-041 |

구현 완료는 실제 폰 성능이나 실측 대비 정확도 검증 완료를 뜻하지 않는다. 해안·중간 격자는 활성화 후 약 3시간까지만 계산하고, 이후 전 지구·발생원 계산과 경험식 판정은 계속될 수 있다.

## 남은 작업과 완료 기준

아래 기준은 후속 작업을 확인하기 위한 기준이다. 구체적인 성능 목표와 구현 순서는 측정 결과를 보고 정한다.

| 작업 | 완료 기준 |
|---|---|
| 날짜변경선 부근의 중첩 좌표 수정 | 변경선을 넘는 부모·자식 격자가 올바른 상대 좌표로 연결되고, 해안 격자의 활성화와 경계 전달이 회귀 검사로 확인된다 |
| 날짜변경선 부근의 침수 판정 수정 | 변경선 양쪽에서 같은 지역 격자 안의 지점을 찾고, 세밀 격자의 처오름·도시 영향 값을 사용한다는 검사가 통과한다 |
| 실제 폰 성능 측정 | 기기·브라우저·시나리오별 준비 시간, 계산 속도, 프레임 시간, 메모리와 되감기 응답 시간을 기록한다. 폰 크기 브라우저 검사와 실제 기기 측정을 구분한다 |
| 침수 띠 주변 메시 세분화 | 좁은 침수 띠가 보이고, 지형 연결 검사에서 능선을 넘어 물이 새는 현상이 줄어든다. 실제 폰의 면 수·프레임 비용도 함께 비교한다 |
| 좁은 해협 처리 | 쓰가루·소야 해협이 거친 격자에서 막히는 문제를 확인하고, 수정 전후 전파와 주변 육지 경계 영향을 비교한다 |
| 해안 구간별 파고 등급 표시 | 해안선 색과 범례로 구간별 등급을 읽을 수 있고, 도시 목록·기존 침수 표시와 혼동되지 않는다 |
| 실측 자료로 시나리오 검증 | 도호쿠 등 시나리오의 관측 위치·도달 시각 정의·출처를 명시하고 계산값과 오차를 함께 기록한다. 기억에 의존한 비교값을 검증 근거로 사용하지 않는다 |
| 되감기 성능 개선 — 필요 시 | 실제 폰에서 되감기가 느린 경우 중간 상태 저장을 검토한다. 도입하면 재계산과 결과가 같고 메모리 비용이 측정되어야 한다 |

앞의 두 항목은 이번 코드 검토에서 확인한 미수정 문제다. 좌표 계산으로 확인했으며, GPU에서 해당 시나리오의 재현 검사는 아직 하지 않았다.

## 보류 중인 상세 모드

상세 모드를 재개하면 다음을 확인한다.

1. 자료 수신 전에 예상 용량·출처·시간·한계를 안내하고 동의를 받는다.
2. 실제 수신량이 안내한 예상치와 [다운로드 예산](DATA-BUDGET.md) 3절의 상한 안에 든다. 초과하면 격자 범위를 줄인다.
3. 실제 지형으로 계산한 결과와 기본 모드의 생성 지형 결과를 화면에서 구분한다.
4. 선택한 해안의 침수 계산과 표시를 검증하고 실제 폰에서 준비 시간과 메모리를 측정한다.

## 검증 기록을 읽는 기준

- 자료 크기와 전송량은 [측정 기록](DATA-MEASUREMENTS.md) 및 [다운로드 예산](DATA-BUDGET.md)을 기준으로 본다. 첫 화면 전송량, 시나리오 추가 전송량, 전체 빌드 크기는 서로 다른 값이다.
- 기존 헤드리스 측정에는 해안 포함 5시간 계산에 95초, 메시 2만 5천~3만 8천 면 생성에 33~50 ms라는 기록이 있다. 소프트웨어 렌더러·데스크톱 CPU 결과이며 폰 성능 근거로 쓰지 않는다.
- D-041에는 RTX 4090을 사용하는 WSLg 환경에서 도호쿠 72시간 계산에 14초가 걸린 기록이 있다. 실제 폰의 성능은 미측정이다.
- 이전 계획의 도호쿠 도달 시각은 계산값 기준 하와이 7.5시간, 미드웨이 4.3시간, 크레센트시티 9.2시간이었다. 당시 비교에 쓴 관측값은 출처 미확인이므로 정확도 검증은 남은 작업이다.
- [프로토타입 품질 게이트](tasks/QUALITY-GATES.md)의 해상도·성능 목표·시나리오 기준은 `src/` 당시 기준이다. 현재 앱의 검사는 `tests/unit/app-*.test.ts`, `tests/e2e/app-solver.spec.ts`, `tests/e2e/globe.spec.ts` 등에서 확인한다.
